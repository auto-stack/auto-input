# AutoInput 共享引擎决策记录（PLAN-078 T-02）

2026-11-25 · 决策记录 · r1 · 关联 [Design 05](05-auto-input-windows.md)、
PLAN-078（`docs/plans/archived/078-autoime-windows-daily-use-closeout.md`）

本记录固定「同一用户数据根只有一个可写词库所有者」的实现路径、进程边界、
提交与学习确认时机、恢复与版本交接，供 T-03/T-04 实施与 T-08 复审核对。
依据是 T-02 的双进程原型和本机实测，不是设计推演。

## 1. 问题与约束

台账 `AUTOIME-LEARNING-SHARING` 的回放表明：两个宿主进程各自加载 librime
时，第二个进程打开 `autoime_user.userdb` 报 `LOCK` 并退化为基础排序；已学到
的「是」在另一窗口不可见，只有全部退出重开才读回。AC-02/AC-03 要求同一用户
数据根的两个常驻宿主双向共享学习、组合相互隔离、正常使用无锁失败、宿主或
所有者退出可恢复。

约束：

- 不改 librime 的排序/学习算法，优先复用其音节匹配与用户词典学习（T-04）。
- 用户数据目录、`custom_phrase.txt`、学习库与现有部署事务（PLAN-072）保持兼容。
- 按键路径的端到端延迟上限 10 ms（P95），冷启与故障等待必须可界定。
- 密码框/隐私范围仍由 TSF 侧判定，不因共享引擎而改变。

## 2. 方案比较

| 方案 | 实际行为 | 结论 |
|---|---|---|
| 各宿主进程内加载 librime，共享同一用户目录 | LevelDB 独占 `LOCK`；后开进程拿不到用户词库，学到的东西只在同进程可见 | 不可行（现状缺陷本身） |
| 只读多开 + 轮询重载 | librime 打开用户库即请求独占锁，没有只读模式；即使可行，也要轮询与重建会话 | 不可行 |
| 文件变更通知 + 重开词库 | 每次确认都触发重开，按键路径出现数十到数百毫秒抖动；仍会在窗口期撞锁 | 不满足延迟与稳定性 |
| 关闭 librime 学习，自研词频排序层 | 能精确控制「确认才学习」，但要重做音节/整词/上下文权重，丢弃已验证机制 | 收益不足，风险高 |
| **单所有者本地引擎进程（选定）** | librime 与用户库只在该进程打开；TSF DLL 只做系统回调、编辑、焦点和候选窗，经本机 IPC 取候选/提交 | 满足 AC-02/03，延迟余量充足 |

## 3. 选定架构

```
宿主进程（记事本/浏览器/…）
  └─ autoime_ime.dll（TSF 文本服务）
       ├─ 系统回调、组合范围、焦点、候选窗（本进程）
       └─ EngineClient ── 命名管道 ──> autoime_engine.exe（每用户一个）
                                          └─ librime 1.13.1 + autoime_user.userdb
```

- 客户端不加载 `rime.dll`，不打开用户目录，因此不存在第二把锁（结构性保证，
  不是「尽力避免」）。
- 引擎进程集中持有 librime 会话：每个客户端会话独立（组合、页、版本互不串扰），
  学习写入同一用户库，所以 A 窗口确认后 B 窗口的下一次组合即可见。
- 协议见 `windows/engine/protocol.h`：24 字节头 + 负载，
  每次请求一个管道消息；协议版本在帧头，版本不一致的客户端被拒绝并重试/自启
  所有者（升级时不混用新旧引擎语义）。
- 管道与单实例互斥名由当前 token 用户 SID 派生
  （`\\.\pipe\autoime-engine-<sid>`、`Local\AutoIME.Engine.<sid>`），
  `PIPE_REJECT_REMOTE_CLIENTS`，连接后在 `Hello` 复核客户端进程的用户 SID；
  不同用户既连不上也顶不掉所有者。

## 4. 所有者生命周期

| 事件 | 行为 |
|---|---|
| 首个客户端需要引擎 | 客户端启动 `autoime_engine.exe --serve`（同一安装目录），等待管道；就绪前按键直通 |
| 第二个引擎被启动 | 用户互斥已存在 → 退出码 8，调用方改用现有所有者（原型已测） |
| 备用/隔离数据根 | 所有者实例按**用户数据根**区分：默认 `%LOCALAPPDATA%\AutoIME\rime` 用无后缀实例；其它根（`AUTOIME_RIME_USER_DATA_DIR`、`--user-data-dir`、测试隔离目录）用 `profile-<路径哈希>` 后缀，拥有独立管道/互斥与独立词库，绝不与默认档案共享学习（2026-11-25 修） |
| 资源版本变化/升级 | 新 DLL 携带新协议/资源版本；所有者退出后由首个新客户端拉起新版本，旧客户端在重连失败期间直通 |
| 所有者崩溃 | 客户端管道读写失败即视为不可用，按键直通；宿主不重开词库；稳定后新的组合重新接入（原型已测：owner 被杀 → ping 失败 → 重启后重连成功） |
| 无人使用 | `--idle-exit-ms` 到期后先 `librime finalize`（刷新用户库）再退出，避免长期占用可写词库 |
| 旧 DLL 仍占用引擎 | 安装/重装时按现有「已加载 DLL 改名停放」处理；引擎与 DLL 分开升级，引擎文件可由安装器安排到下次空闲替换 |
| 宿主仍映射锁定数据 | 升级安装不得替换被宿主映射的 `rime.dll`/`data\`（相同锁定版本用 `onlyifdoesntexist` 跳过）；真正的引擎升级走需要重启的安装包，避免 Inno 在「文件占用」处中止并回滚（2026-11-25 实测） |

启动耗时（本机实测，空用户目录 + 首次部署）：3445 / 3565 / 4487 ms；资源未变
时重启 600–857 ms。就绪前的按键按现有合同直通，不阻塞宿主。

## 5. 提交与学习确认

T-04 落地（2026-11-25）：补充词表 `autoime_words` 的 translator 改为
`enable_user_dict: true` + `user_dict: autoime_user`，与主拼音共用同一学习域，
补充词确认不再被丢弃，全拼/简拼/混输共享同一份权重。`autoime_terms` 保持不
学习：项目术语只有精确长码且已排在自身编码首位，重复确认只会放大术语权重。
验收 oracle 取「确认后用户词库确实增长、取消不增长」而不是排名（「是的」本来
就是第 1）。

librime 在「确认候选」时更新用户词典，因此学习的唯一发生点是引擎的
`select`；提交文本只交付一次（`TakeCommit` 语义为消费）。为了满足
「取消或失败不计入」，协议增加显式确认：

| 客户端动作 | 引擎行为 |
|---|---|
| `Select(page_index)` | 引擎确认候选并产生提交文本（此时用户库已学习） |
| `Commit()` | 返回并消费提交文本，只交付一次 |
| `Confirm(session)` | 宿主成功写入正文：记录一次成功确认，无需补偿 |
| `Forget(session, code, text)` | 宿主写入正文失败：引擎用同一编码开临时会话，按文本定位候选并 `delete_candidate_on_current_page` 删除该用户词条，排名回到系统基线 |
| Esc/宿主终止组合 | 不产生 `select`，不学习 |
| 重复点击/过期页 | 页版本与页内索引校验拒绝，不产生第二次提交或第二次学习 |

原型验证（`AUTOIME-LEARNING-SHARING` 复现路径）：`lixian`→「李显」基线第 2，
连续确认 3 次升到第 1（同进程第二个会话、另一进程的新会话同样第 1）；
随后 `Forget("lixian","李显")` 使排名回到第 2，再确认后重启所有者仍为第 1。

## 6. 数据兼容与版本交接

- 用户数据目录、方案资源、`custom_phrase.txt`、`autoime_user.userdb` 均沿用现有
  位置与格式；引擎与 DLL 读取同一 `%LOCALAPPDATA%\AutoIME\rime`。
- 资源部署仍由所有者执行（复用 `RimeEngine::EnsureReady` 的版本哈希、回退与
  上一可用版本逻辑）；部署/管理器不再各自打开可写词库，而是与所有者协调
  （T-05 的术语事务、T-03 的部署协调）。
- 协议版本写入每个消息头；不匹配一律拒绝，不做「尽量兼容」的部分解析。

## 8. 交给 T-03/T-04 的合同

1. `RimeEngine` 增加 remote 模式：`CreateSession/ProcessKey/GetContext/Status/
   SetOption/SelectCandidateOnPage/TakeCommit/Clear` 经 `EngineClient` 转发，
   `EnsureReady` 变为「连接或拉起所有者并等待就绪」；TSF 侧回调、编辑、焦点、
   候选窗代码保持不变。
2. TSF 提交成功后调用 `Confirm`；正文写入失败调用 `Forget`，失败本身按现有
   合同报告，不重试成第二次学习。
3. 部署/管理器与所有者协调：术语与短语事务通过引擎执行或在其锁内重载，
   不允许再次出现「多个工具并行加载可写词库」。
4. T-04 用实际学习记录与排名变化验证：一次成功提交一次学习、取消与宿主失败
   不计入、不同拼法共享、重启与升级保留。
5. V-02/V-04 的真实宿主部分（记事本 + 浏览器文本框双向选词、关闭 A 后 B 继续）
   仍按计划在 T-07 的离线包走查中完成；本记录只冻结架构与接口。

## 9. 残余风险

- 引擎崩溃发生在「已学习、未返回提交」之间时，该次确认的学习会保留而正文未
  写入；用户可用现有遗忘路径（候选删除）纠正，影响限于单个词条。
- 所有者退出与宿主重启之间的组合会被取消（沿用现有失焦/终止语义），不重放。
- 若第三方输入法工具直接打开 `%LOCALAPPDATA%\AutoIME\rime`，仍会与所有者竞争；
  发行版不提供此类入口，管理器统一走引擎/部署事务。
