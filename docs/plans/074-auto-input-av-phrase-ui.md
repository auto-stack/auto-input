# PLAN-074 · AutoInput AV 图形短语管理器

## 0. 变更摘要

以新版 ACE AV 和 AutoUI 原生桌面组件构建短语管理窗口，复用 072 的 Auto 业务与事务部署能力。用户通过列表与表单增删改、导入导出并看到实际部署结果。GUI 与 CLI 消费同一份个人短语数据。

## 1. 目标

从 Windows 开始菜单打开 AutoInput 短语管理器，搜索短码或文字、编辑条目、保存并在新记事本会话中输入。保存失败可看到原因并保留当前编辑内容。界面使用 Auto 源编写，由新版 AV 执行，随现有离线安装包交付。

本包范围为个人短语及其部署状态。候选窗样式设置、全局热键、Launcher 联动、云同步、Linux UI 和 A2R 发布迁移分别留待后续规划。

## 2. 架构方案

AutoUI 视图/typed 事件 → AV 中的管理状态 → 072 的共享短语服务 → 072 原生事务应用工具 → 新会话候选验证。界面只在服务确认结果后显示已应用，busy/冲突/回滚状态沿 072 的业务合同显示。

优先直接导入 072 的 Auto 业务模块，适配现有 CLI 入口为可复用调用；若桌面宿主与模块执行环境暂有差异，可使用 072 的结构化命令接口，通过已有受检进程能力调用。T-01 固定唯一适配方式和结构化返回格式，禁止解析供人阅读的输出文本或在 UI 内复制 TSV 校验/事务逻辑。

GUI 是独立管理进程。AutoUI/AGE 的组件和宿主能力是本包的实际依赖；输入法 TSF 产品域继续独立运行。当前目标为新版 AV 的 Windows 原生窗口，A2R 由后续迁移验收。

## 3. 技术栈

新版 ACE AV、AutoUI 原生桌面入口及既有组件、072 管理模块与 helper、Inno Setup 6。实现主面在 auto-os 的 `manager/`，使用拟定工作树 `D:/autostack/auto-input`、在 `main` 上开发，执行与复审顺序复用。

按环境变量/兄弟检出/主检出顺序解析语言和 UI 仓。若发现框架能力缺口，在 auto-ui 或 auto-lang 的对应 owner 留最小复现和关闭条件，再接续依赖任务。本计划自身消费已交接口，框架实质修改沿所属仓计划规约办理。

## 5. 详细设计

拟新增 `manager/src/ui/app.at`、`store.at` 和 `manager/tests/phrase-ui.case.ad`，按 T-01 的真实 pac/工程结构调整。`store.at` 只持有搜索、选择、表单草稿和操作状态；数据规则与提交职责复用 072。

窗口采用列表加编辑区。列表展示短码、文字、权重，支持搜索与选择；编辑区提供新增/编辑/删除、保存、取消；导入/导出提供文件选择及可编辑路径。初始状态显示真实数据与当前用户目录，错误直接呈现在对应字段或操作结果处。

修改短码等同于修改复合键，由业务层在一次操作中处理原条目和新条目；若 072 接口尚无此原子操作，由本计划扩展该共享业务模块和 CLI 同源用例，禁止 UI 分两次提交造成旧条目丢失。取消、关闭和切换条目对未保存草稿给出保留/放弃选择。删除需确认目标条目，重复点击保存只触发一次有效操作。导入整批成功后刷新列表，非法文件显示行号和原因。

每次后台操作关联当前请求版本。耗时部署不阻塞 UI 事件循环；离开窗口、修改草稿、重复请求后的迟到结果不得覆盖新草稿。文件被 CLI/外部编辑修改时，按 072 冲突语义提示重新加载，保留用户尚未提交的文字。成功状态区分已写入、部署成功、新宿主可见以及明确需要重开宿主的状态。

管理器自身文本框必须支持中文 IME 组合、选区替换和取消。中文组合中的 Enter 只按输入控件的组合语义处理；保存和快捷键不得导致半截拼音保存或重复提交。测试包括用 AutoInput 在短语文字框输入中文，从而覆盖输入法与管理器的真实配合。

新增开始菜单“AutoInput 短语管理器”入口，随 071/072 安装脚本和 AV 运行材料打包。启动定位包内资源，用户数据定位当前账户；关闭管理窗口后退出其进程。CLI/GUI 共用版本和数据格式，升级与卸载沿现有保留合同处理。
